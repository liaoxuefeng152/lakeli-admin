# 域途 GEO SaaS · 网络安全等级保护三级合规设计（NF6）

> 文档版本：v1.0
> 适用范围：域途 GEO SaaS 插件（geo/*）及其依托的「拉克力管理后台」统一底座（lakeli-admin-web 前端 + lakeli-app-xc 后端 + PostgreSQL）
> 对标标准：GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第三级

---

## 1. 文档目的

域途 GEO SaaS 作为面向企业的 AI 优化 SaaS 产品，处理客户品牌词、内容素材、监测数据及企微会话等敏感业务数据。按照《网络安全法》与等保 2.0 要求，承载此类数据的系统应至少按**第三级（S3A3）**进行保护与测评。

本文档：
1. 梳理等保三级核心控制项与本系统的落地映射；
2. 明确**已具备**的安全措施与 **NF6 待整改差距项**；
3. 给出可执行的整改路线与测评推进计划。

---

## 2. 等保三级核心控制项映射

| 控制类 | 三级核心要求 | 本系统现状 | 差距 |
|--------|--------------|------------|------|
| 安全通信网络 | 通信传输加密（TLS）、网络架构冗余 | 前端经 HTTPS 访问；API 经 `next.config.ts` rewrites 代理至后端 | 需确认后端 5002 强制 TLS、禁用明文 HTTP |
| 安全区域边界 | 边界防护、访问控制、入侵防范 | 统一 API 网关代理，无明显边界隔离 | NF6-1：补充 WAF / 速率限制 / 黑白名单 |
| 安全计算环境 | 身份鉴别（双因子）、访问控制、入侵防范、恶意代码防范、可信验证 | 已具备登录鉴权 + RBAC 角色矩阵 + 操作日志 | NF6-2：缺少双因子（MFA）；NF6-3：缺少主机/容器入侵检测 |
| 安全计算环境-数据 | 数据完整性、保密性、备份恢复、个人信息保护 | 统一模型配置 `ai_models` 含 `api_key`/`api_base_url`；操作日志留存 | NF6-4：密钥明文存储需改造为 KMS/密钥托管；NF6-5：敏感字段（企微会话、客户档案）落库需加密 |
| 安全管理中心 | 系统管理、审计管理、集中管控 | 操作日志（`/operation-log`）+ 活动日志 | NF6-6：缺少统一审计归集与告警；NF6-7：缺集中日志（SIEM） |
| 安全管理制度 | 策略、机构、人员、建设、运维 | 暂无成文安全管理制度 | NF6-8：补齐制度文档与岗位职责 |

## 3. 已落地的安全措施（现状基线）

- **身份鉴别与授权**：`src/lib/auth.tsx` 封装登录/登出与会话持久化（localStorage）；`(dashboard)/layout.tsx` 路由守卫未登录跳转 `/login`；`sidebar.tsx` 按 `ROLE_ACCESS` 矩阵按角色（admin/operator/sales/user）过滤菜单。后端 `/api/auth/login` 走 `lzg.users` 表，role 枚举受控。
- **审计能力**：`/operation-log` 与活动日志页面提供操作审计查看入口；关键写操作（模型配置、配额、知识条目）应写入审计。
- **租户隔离**：GEO 监测/文案/知识均按租户隔离；统一模型配置（`/platform/models`）集中管理 LLM，避免密钥散落。
- **传输安全**：前端默认 HTTPS 部署；API 统一经网关代理，避免前端直连数据库。

## 4. NF6 差距整改项（落地清单）

| 编号 | 整改项 | 优先级 | 建议方案 | 负责模块 |
|------|--------|--------|----------|----------|
| NF6-1 | API 边界防护（限流/防刷/黑白名单） | 高 | 网关层接入 WAF + 基于 IP/账号的速率限制；外呼、监测等高频接口加熔断 | 后端网关 |
| NF6-2 | 双因子认证（MFA） | 高 | 登录增加 TOTP/短信二次验证；超管强制开启 | auth 链路 |
| NF6-3 | 主机/容器入侵检测 | 中 | 部署 HIDS（如 OSSEC/Wazuh）+ 镜像漏洞扫描 | 运维 |
| NF6-4 | 密钥保密性改造 | 高 | `ai_models.api_key` 等敏感字段改为 KMS 托管 / 字段级加密，应用侧不落明文 | 模型配置 |
| NF6-5 | 敏感数据落库加密 | 中 | 企微会话存档、客户档案 PII 字段加密存储 + 访问脱敏 | 数据中台/企微 |
| NF6-6 | 统一审计归集与实时告警 | 中 | 操作日志统一上报审计中心，异常操作（批量导出、禁用账号）实时告警 | operation-log |
| NF6-7 | 集中日志与 SIEM | 中 | 应用/网关/主机日志统一采集至日志平台，保留 ≥180 天 | 运维 |
| NF6-8 | 安全管理制度文档 | 低 | 补齐安全策略、岗位职责、应急预案、供应商管理文档 | 合规 |

## 5. 测评推进路线

1. **定级备案（第 1 月）**：完成系统定级报告，向公安机关备案。
2. **差距整改（第 1–2 月）**：按 NF6-1~NF6-8 完成高优项（NF6-1/2/4），中低优项排期。
3. **等级测评（第 3 月）**：委托具备资质的测评机构开展三级测评，出具测评报告。
4. **持续运营（长期）**：定期开展漏洞扫描、渗透测试、应急演练与合规复审。

### 7.1 状态汇总（截至 2026-07-28）

- **代码侧已具备基线**：身份鉴别与 RBAC（`src/lib/auth.tsx` / `sidebar.tsx`）、操作审计入口（`/operation-log`）、租户隔离、HTTPS 传输、统一模型配置集中管理（`/platform/models`）。
- **需后端 / 外部依赖方可闭环**：NF6-1/2/4/5（网关、MFA、KMS、加密）、NF6-3/7（HIDS、SIEM 供应商）。
- **当前仓库前端范围内可直接落地的改造**：NF6-6 审计告警前端呈现与操作日志字段补全；其余须在 `lakeli-app-xc` 后端与服务采购侧推进。
